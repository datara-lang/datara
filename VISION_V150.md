## 1. Миссия и позиционирование

**Datara** — универсальный компилируемый язык, который должен:

- Быть быстрее или на уровне Rust/C в hot path (подтверждается замерами, не лозунгами).
- Быть проще Python в быту (уровень 1: пишешь `val x = ...` и не думаешь о памяти).
- Давать полный контроль, когда он нужен (уровень 4: регистры, MMIO, asm) — без аннотационного налога на остальных уровнях.
- Не иметь GC-пауз вообще — ни в системном коде, ни во фронтенде, ни в браузерном ядре (см. §3 TMM).
- Быть безопасным по умолчанию: capability-модель `[Net]/[FS]/[Env]`, fail-closed инварианты, ни одного UB-пути.
- Соблюдать кроссплатформенность без жертв: Windows/Linux/macOS/嵌入式/MCU — одна и та же языковая модель.

Ключевое отличие позиционирования: **мы не заставляем мир переписываться на Datara.**
Мы даём возможность писать НОВЫЕ модули, сервисы, библиотеки и интерфейсы на Datara
рядом с существующим кодом (мосты: C/Rust/Python/JS/npm/Zig/Lua/C#), а дальше люди
сами выбирают темп миграции. Язык, который «для всего»: банк — ок, HFT — ок,
фронтенд — ок, ОС для ракеты — ок, прошивка микроконтроллера — ок.

Ниши-первопроходцы (где Datara уникален уже в 1.5.0):
1. **Фронтенд без GC** (через будущий браузерный движок и WASM-путь).
2. **Детерминированная память** (TMM — §3): ниша между Rust (сложно) и Go (GC).
3. **Универсальность уровней в одном файле** (§2): скриптовая простота и kernel-контроль рядом.

## 2. Философия уровней: 4 уровня, «ниже уровень — выше контроль»

Существующая архитектура (README v1.4.5) сохраняется и является скелетом всей идеологии:

| Уровень | Назначение | Инструменты | Ментальная нагрузка |
|---|---|---|---|
| 1 — Scripting | Прототипы, утилиты, учётка, glue | `val/mut`, `fmt"..."`, List/Map, авто-память | нулевая |
| 2 — Enterprise | Сервисы, API, прод-логика | require/ensure, `?`/`or`, capability-аннотации, типы ошибок | низкая |
| 3 — Systems | Драйверы, протоколы, hot path | view/zero-copy, @arena/@pool, @packed, endianness, RawPtr+unsafe | средняя, явная |
| 4 — Kernel | MMIO, ядра ОС, прошивки | VolatilePtr, fences, asm{}, typed_zero_init | максимальная, изолированная |

**Правила уровней (незыблемые):**

1. **Никто не выбирает уровень для всего проекта.** Уровень выбирается для КУСКА кода,
   неявно, тем, что человек пишет. В одном файле, в одном цикле могут сосуществовать
   уровень 1 и уровень 4. Никаких toml-переключателей «какой уровень включить» —
   уровень это свойство выражения, не конфига.
2. **Чем ниже уровень — тем больше контроля и тем больше явности. Но явность локальна:**
   она не протекает в вызывающий код уровня 1.
3. **Компилятор несёт сложность, а не пользователь.** На уровне 1 пользователь не видит
   ни lifetime, ни указателей, ни аллокаций. На уровне 4 он видит всё — но только там.
4. **Скорость одинакова на всех уровнях.** Уровень 1 компилируется в тот же машинный
   код, что и уровень 3, когда escape-анализ это позволяет. Простота не стоит производительности.

Следствие для новичка и сеньора (требование владельца):
- Новичок начинает на уровне 1 и никогда не встречает указатель.
- Сеньор держит в голове только то, что даёт контроль, и не держит то, что компилятор
  может отсечь. Его церемонии (borrow checker Rust) заменены компиляторной машинерией (TMM §3).

## 3. TMM — Temporal Memory Model (флагманская технология)

### 3.1 Суть

Три слоя управления памятью, компилятор выбирает слой автоматически; пользователь
управляет только когда хочет. **Ноль GC, ноль рантайм-счётчиков по умолчанию.**

| Слой | Что | Рантайм-цена | Когда выбирается |
|---|---|---|---|
| Layer 1 | Dataflow lifetime inference: компилятор находит ПОСЛЕДНЕЕ использование объекта в dataflow и вставляет free сразу после него (не в конце scope) | ноль, по определению | по умолчанию для всего |
| Layer 2 | Regions: @arena, @pool(n) — групповое освобождение | ноль (bump-pointer) | циклические структуры, пакетные задачи, явные @arena |
| Layer 3 | @arc: атомарный счётчик, детерминированное освобождение при нуле | счётчик-инкременты | shared ownership, замыкания, переживающие фрейм; по явному @arc или автоматически для таких захватов |

### 3.2 Почему это уникально

- Rust: безопасность через borrow checker = церемонии у пользователя ('a, &mut, PhantomData).
- Go/Java/JS: простота через GC = паузы и рантайм.
- Swift/Perceus/Koka: близко к Layer 1 (reuse analysis), но академично/с рантаймом ARC.
- **Datara: все три слоя + автоматический выбор + нулевой синтаксис по умолчанию.**
  Ни один production-язык этого не делает. Это заявка на нишу на 5–10 лет.

### 3.3 Решения известных проблем (дизайн-контракты)

| Проблема | Решение | Статус в плане |
|---|---|---|
| Compile time растёт | Инкрементальный lifetime-граф по модулям: пересбор только изменённых | M6 |
| Замыкания/callbacks переживают фрейм | Автоопределение захвата → объект в Layer 3 (@arc) только для этого объекта; остальное остаётся Layer 1 | M5 |
| Циклические графы | Статический детектор циклов ownership-графа → предупреждение «поставь @weak здесь»; одна аннотация | M5 |
| Авто-arena для циклов | Обнаружение цикла → регион автоматически (или подсказка) | M6 |
| Сложно отлаживать память | `forgen inspect --memory`: аннотированный листинг — где что освобождается, какой слой | M5/M6 |
| FFI-границы | `owned`/`borrowed` маркеры на extern-сигнатурах; Datara знает о владении, C — нет | M5 |
| GC-паузы | Их нет по построению: L1/L2 — ноль рантайма; L3 — наносекундный декремент, без stop-the-world | везде |

### 3.4 Контроль без потерь

Пользователь всегда может:
- Ничего не писать (Layer 1 по умолчанию).
- Сказать «арена» (`@arena`) — получит регион.
- Сказать «шарить» (`@arc`) — получит счётчик.
- Сказать «я сам» (`unsafe { }` + RawPtr) — получит полный контроль, изолированный capability-моделью.
- Проверить решение компилятора (`forgen inspect --memory`) — прозрачность по запросу.

«Человек хочет — так и будет, без каких-либо лишений»: желание выражается аннотацией,
неfight с компилятором. Компилятор никогда не «чинит» желаемую семантику — только
доказывает её безопасность или отказывает с объяснением (Diagnostics Gold, M2).

### 3.5 Связь с существующим

| Есть сейчас | Становится в TMM |
|---|---|
| require/comptime/контракты | помощь доказательству Layer 1 |
| unsafe { justification } | явный opt-out (Layer 4), capability-изолирован |
| @arena/@pool | Layer 2, уже в рантайме |
| @derive(...) | расширяется на @arc/@weak/AutoFree |
| behavior/role контракты | ownership-контракты |
| view (zero-copy) | заимствование без аннотаций — уже работает |

### 3.6 Честные границы v1.5.0

Layer 1 — 2–4 месяца серьёзной работы. В 1.5.0 гарантируется: однонаправленное
владение (деревья/DAG) — полное; циклы — авто-arena или подсказка @weak.
Escape-анализ двунаправленных графов общего вида — горизонт (§14).

## 4. TSU — Type-Set Unboxing (динамика без бокса)

Идея: `val x = <что угодно>` не значит «боксуй». typechecker строит TypeSet по flow:
- сеты объединяются в точках слияния, ветвления сужают;
- `if x is Int` — в ветке сет вырожден → код статический, проверка тега одна на входе или ноль;
- представление: { tag: u8, pad: 7, payload: 8 } = 16 байт; примитивы — raw, без бокса;
- мостовое применение: py.eval_any(...) → val — Python-динамика без PyObject-налога.

Философия: «динамика — это не рантайм, это незнание на момент написания». Если flow
доказал тип — код должен быть статическим. Уровень 1 получает Python-гибкость с
нулевым runtime-налогом, когда это возможно; когда невозможно — платит 16 байт и
одну проверку тега, не миллисекунды.

## 5. Веб-стратегия: Datara рядом с вебом

### 5.1 Принципы

1. **Никакого JS-налога.** Datara компилируется в WASM (capability-native путь уже есть)
   и в натив для SSR-серверов. Логика фронтенда пишется на том же языке, что и бэкенд.
2. **Обратная совместимость с HTML5/CSS — обязательна** (требование владельца): люди
   должны уметь переходить без боли. Но целевой путь — новый синтаксис.
3. **Новые расширения вместо новых языков**:
   - `.dtrml` — разметка (переосмысление HTML: семантика без 30 лет легаси, строгая
     вложенность, типизация через comptime-шаблоны, XSS-безопасная интерполяция по умолчанию);
   - `.dtrf` — фронтенд-модуль на Datara (компоненты, состояние, события — всё на нашем
     языке; никакого JS/TS);
   - стили: свой CSS-подобный синтаксис внутри .dtrml с обратной совместимостью с CSS-правилами.
4. **Монолитность внутри .dtr**: один .dtr-файл может содержать разметку, стили и логику
   (inline-блоки), либо .dtrml/.dtrf могут быть отдельными файлами. Решение «оставить
   только .dtr» — открытое; финальный дизайн фиксируется до старта браузерного ядра
   (PLAN H-пункт). Оба режима должны поддерживаться: файл для быстрого, проект для большого.

### 5.2 Что уже есть для этого в 1.4.5

- WASM-бэкенд с capability-импортами и JS-shim (runtime-паритет v1.4.5).
- fmt-интерполяция (comptime-шаблоны SSR выросут из неё — M12).
- js-мост (браузеры говорят с DOM через js-бридж — M12, тонкие обёртки).
- zero-GC память (TMM) — фронтенд без пауз, чего нет ни у одного JS-фреймворка.

### 5.3 Порядок (безопасный путь)

M12 (SSR + http + DOM-мост, «Datara рядом с существующим вебом») → практика на реальных
проектах → дизайн dtrml/dtrf → браузерное ядро (горизонт, §6).

## 6. Браузерное ядро — концепция (горизонт, после 1.5.0)

Замысел владельца, зафиксированный как долгосрочная цель:

- **Новый движок** на Datara: переосмысление браузера без легаси Chromium/Firefox.
- Цель совместимости: открывать ~80% современных сайтов (новые технологии); старый
  легаси-веб и банки — через режим совместимости или не поддерживать сознательно.
- **Zero-GC рендер-конвейер**: TMM означает отсутствие GC-пауз в UI-потоке — плавность,
  недостижимая для JS-стека.
- **Геймдев-grade UI**: то же ядро рендерит 2D/3D игры и интерфейсы (уровень рендера —
  wgpu-мост, уже в горизонте PLAN); UX-слой отделён, не мешает играм (turbolike
  windowing/input/audio — M11 — фундамент).
- **HFT внутри браузера**: детерминированная память и латентность (HFT Pack в горизонте).
- **Кастомизация**: браузер как платформа — пользовательские модули на любом языке
  (через мосты) без потери производительности.
- **Приватность**: без слежки, конфиденциальность по умолчанию, capability-модель
  контролирует сет/фс/окружение на уровне языка.
- **Tauri-подобная упаковка**: приложения на Datara + ядро = десктоп-приложения нового
  поколения (лёгкие, быстрые, безопасные).
- Первый этап: ядро + базовый интерфейс (именно базовый, чтобы не мешать играм).

Почему язык должен быть готов раньше ядра: ядро — это сотни тысяч строк системного
кода; писать его на языке с TMM/TSU/NatVar/уровнями — в разы безопаснее и быстрее.
Отсюда порядок: 1.5.0 (PLAN) → dtrml/dtrf → ядро.

## 7. Самохостинг — стратегия (аналог Zig/Rust/Go)

Исторический паттерн (все прошли через него):
- Rust до сих пор на LLVM; Cranelift — для debug.
- Zig держал LLVM, свой бэкенд строил годами (stage3).
- Go держал C-компилятор, пока не написал gc на Go.

**План Datara (этапность, без риска для стабильного пути):**
1. Утилиты тулчейна — на Datara (скрипты сборки, генераторы, инструменты) — сразу после M1.
2. Отдельные фазы компилятора (fmt-движок, линтер правил, doc-генератор) — на Datara,
   когда TMM Layer 1 стабилен (доказательство: компилятор сам использует авто-память).
3. Stage2-компилятор — долгий горизонт; Cranelift/LLVM остаются до полной замены.

Критерий перехода компонента: Datara-версия быстрее или равна Rust-версии по замерам,
и тестовое покрытие эквивалентно. Никакой идеологии ради идеологии.

## 8. NatVar — философия async (в PLAN: M10)

Асинхронность без раскраски: любой код работает внутри корутины прозрачно —
нет async fn, нет state-machine boxing, нет синтаксического разделения мира на
sync/async (главная боль Rust/tokio). Фиберы (stackful) + work-stealing + IO-поллеры
(epoll/IOCP/kqueue). Ошибки — через родной Outcome. Мьютексы без poisoned-state.
Сравнение с tokio — честными цифрами, не лозунгами.

Почему это важно ядру браузера: сетевой стек движка и веб-серверы на Datara должны
держать десятки тысяч соединений без выделенных потоков — и тот же рантайм остаётся
полезным обычным пользователям (лёгкий async для всех).

## 9. Экосистема: sparks и dpm — роли и различия

| | dpm | sparks |
|---|---|---|
| Что это | Менеджер пакетов (CLI, входит в тулчейн) | Центральный реестр пакетов |
| Где | `src/project/pm/` (бины dpm, `forgen install`) | `D:\DATARA\sparks` → GitHub Pages (datara-lang.github.io/sparks) |
| Аналогия | cargo/npm-клиент | crates.io/npm-реестр |
| Безопасность | verify-подписи, lock-файлы | Ed25519-подписи (ключ datara-core-2026-v2), capability-sidécars (.capabilities.json) против supply-chain |
| Статус 2026-09-21 | Полный CLI: init/add/remove/install/verify/search/info/publish/run/... | Реестр живой, 0 опубликованных пакетов; seed-пакеты (mathx/strx/jsonx) в tests/fixtures |

Решение владельца о новых библиотеках (NatVar, windowing и т.д.): всё, что пишется
для ядра браузера и может быть полезно вне его, выносится в библиотеку. Куда именно —
решать по существу: базовые примитивы → stdlib; специализированное → sparks-пакет.
Критерий: если фича нужна каждому (таймеры, сокеты, коллекции) — stdlib; если нише
(SDL-обёртки, тензоры) — sparks.

## 10. Универсальность и «мы никого не заставляем»

Язык для всех ниш (банки, HFT, сервисы, фронтенд, ОС, МК, игры) — но стратегия
внедрения: новые модули на Datara рядом с существующим кодом (мосты C/Rust/Python/JS/
npm/Zig/Lua/C#). Не переписывание, а прирастание. Поэтому мосты — гражданин первого
класса: `forgen bridge check`, bridges-матрица в CI (PLAN M13), нулевые накладные
расходы на границе (C 0 ns уже подтверждено доктором мостов v1.4.0).

## 11. Кроссплатформенность без жертв

- Одна языковая модель на всех платформах; бэкенды скрывают различия ABI.
- Windows x64 — первая сцена (уже); Linux x64, macOS — CI; ARM64 всех трёх — горизонт;
  MCU (thumbv7m/RISC-V) — через LLVM-путь + no_std-режим рантайма.
- Репродьюсибл-билды — горизонт; детерминизм компиляции уже заявлен как принцип
  (bit-exact, IEEE-754 identity).
- Ни одна фича PLAN не должна предполагать «только Windows»: пути, разделители,
  endianness, фиберы — везде с нативной реализацией.

## 12. Обратная совместимость — политика

**До v1.5.0** (включая процесс работы над 1.5.0): можно ломать и переосмыслять —
мы ещё лепим форму (Str/String-унификация, let→val-миграция — примеры).

**С тега v1.5.0**: обратная совместимость ОБЯЗАТЕЛЬНА. Правила:
1. Обновление языка не ломает существующий корректный код.
2. Устаревание: сначала warning (canonical-keyword стиль W-SYN), потом удаление не раньше +2 minor-версий.
3. Диалекты/режимы не вводим — один язык, одна правда.
4. ABI-контракты (рантайм, layouts, bridge-примитивы) замораживаются документом docs/abi.md
   (PLAN H) — изменение = breaking 2.0.
5. `forgen migrate` — механический перенос старых исходников при редких breaking-изменениях.

  stdlib reference, архитектура «как внутри и почему именно так», мосты. Стиль:
  просто, чтобы любой программист понял; без внешних JS; тёмная тема.
- **Diagnostics как продукт**: каждый код ошибки объясняется с примером (M2);
  `forgen explain` — первый помощник; machine-fixes — второй.
- **Уровни для новичка и сеньора** (§2): новичку — простота и защита; сеньору —
  контроль без церемоний. Компилятор объясняет, а не ругается.

## 15. Глоссарий

- **Datara** — язык. **Forgen** — тулчейн/компилятор (Cranelift JIT/AOT, LLVM, WASM).
- **dpm** — менеджер пакетов. **sparks** — центральный реестр пакетов (Ed25519).
- **TMM** — Temporal Memory Model, 3 слоя памяти (§3).
- **TSU** — Type-Set Unboxing, динамика без бокса (§4).
- **NatVar** — собственный async-рантайм без раскраски (§8).
- **Уровни 1–4** — Scripting/Enterprise/Systems/Kernel (§2).
- **Capabilities** — [Net]/[FS]/[Env] sandbox-модель; unsafe не пробивает их.
- **Evidence Gate** — fail-closed SSA-верификатор оптимизаций.
- **dtrml/.dtrf** — будущие веб-форматы Datara (§5).
- **Outcome<T>/Maybe<T>** — типы ошибок/опциональности; `?` и `or` — работа с ними.
- **val/mut** — канонические биндинги (let — легаси, миграция в PLAN M0).
