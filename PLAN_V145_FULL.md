## 1. ПЕРЕМЕННЫЕ: `val` / `mut` БЕЗ `let` (новая система)

### 1.1 Решение
Убрать обязательный `let`. Новый синтаксис:

```datara
val x = 10          // иммутабельная (ранее let)
mut y = 0           // мутабельная (ранее let mut)
val z: Int8 = 100   // с типом
```

- `val` = bind-once, иммутабельная, **компилятор имеет право инлайнить** значение по месту использования без анлайза.
- `mut val` форма из заготовки парсера — **удаляется** (слишком много). `mut` уже значит мутабельность.
- `let` **сохраняется как синоним `val`** на переходный период (1–2 версии) + warning «use val», потом удалить. Ничьи старые примеры не ломаются.

### 1.2 Чем это прорыв (если додумать до конца)
Нигде нет этого:
1. **`val` — это обещание производительности, не запрет.** val-переменная доступна в comptime-выражениях как кандидат на подъём: если выражение константа — считаем на компиляции (градиент времени вычисления: comptime → val → mut).
2. **val = сигнал оптимизатору**: разрешаем constant-propagation и инлайн без анализа escape. Мутабельность заявлена в объявлении = компилятору не нужен анти-анализ (у Rust это borrow-checker, у нас — статическое обещание).
3. **Эргономика**: `val x = 5` — на 3 символа короче Rust `let x = 5`, и читается как «значение».

### 1.3 Задачи (этап W5)
- [ ] Lexer: убрать `Val` из ветки `let mut val` парсера; `Val`-токен стартует объявление сам
- [ ] Parser: `val NAME [: T] = expr` и `mut NAME [: T] = expr` (без `let`)
- [ ] `let`/`let mut` → parsing ok + warning E-WARN «deprecated: use val/mut» (двойной синтаксис 2 версии)
- [ ] Типы/чекер: `val` попадает в symbol table с флагом `immutable_opt` → const-propagator в optimizer/const_fold.rs использует его агрессивно (инлайн по месту, если expr — pure)
- [ ] comptime-градиент: `val x = <pure expr>` где всё константно → значение вычисляется в компиляции, помечается как ConstInt в D-MIR
- [ ] Обновить ВСЕ примеры examples/ и tests/ на новый синтаксис
- [ ] Тесты: parser (new + legacy), checker (попытка присвоить val → ошибка с подсказкой «объяви как mut»), optimizer (val инлайнится)
- [ ] README + docs: глава «Variables: val & mut»

## 5. ПАМЯТЬ: АРЕНЫ + OWNERSHIP (лучше Rust без боли)

### 5.1 Философия (зафиксировать в docs)
- **Компиляционное владение** (как Rust) — уже есть, чекер проверяет
- **Arena/region** — уже есть в runtime (28 узлов gc/arena в коде)
- **Никакого трассирующего GC** — пауз нет в принципе, освобождение привязано к скоупу функции
- **unsafe — единственный проход к RawPtr** (как у Rust, но у нас честнее: эффект-система пишет это в capability-отчёт)

### 5.2 Уникальная фича, которую доделать (этап M1)
- [ ] **Регион на вызов функции** (неявная арена): все аллокации внутри функции — в её регион, освобождение одним махом при выходе. Разработчик не думает. Rust так не умеет (у него drop по объекту).
- [ ] **Проверка «регион не утёк»**: возврат указателя на арену функции → ошибка компиляции с текстом «значение живёт в арене функции foo(); верни скопированное значение или объяви Box»
- [ ] **`val`-переменные всегда в стеке** (если не Box) — ноль аллокаций для иммутабельных данных
- [ ] Документация: глава «Memory model: regions, ownership, Box» — 5 страниц простым языком

## 9. ТИПЫ: ЧЕГО НЕ ХВАТАЕТ ДЛЯ «ВЗРОСЛОГО» ЯЗЫКА (этап T1)

Приоритет по важности:
1. **enum с payload + pattern matching**
   ```datara
   enum Shape { Circle(r: Float), Rect(w: Float, h: Float), Point }

   fn area(s: Shape) -> Float {
       return match s {
           Circle(r) => 3.14159 * r * r,
           Rect(w, h) => w * h,
           Point => 0.0
       }
   }
   ```
   Это убирает главный «неполный язык»-статус. Чекер: exhaustiveness (все ветки покрыты — иначе ошибка).
2. **Generics второго уровня**: `fn max<T: Comparable>(a: T, b: T) -> T` (сейчас ограничены); мономорфизация на D-MIR (как в Rust — без runtime-стоимости)
3. **trait/behavior-констрейнты** в сигнатурах (behavior уже есть — расширить до bounds)

Задачи:
- [ ] AST: Expr::Match, Decl::Enum
- [ ] Parser + resolver + checker (exhaustiveness!)
- [ ] 3 бэкенда + comptime-совместимость (enum в comptime)
- [ ] Тесты: match-раскрытие, enum-деструктуризация, generic-мономорфизация

## 14. ПОЗИЦИОНИРОВАНИЕ (для README и сайта)

> **Datara** — компилируемый язык, который быстрее C в hot path, проще Python в написании, и работает от микроконтроллера до браузера без переписывания. Мосты к Python/Rust/C/npm вместо конкуренции с ними.

Демо на 2 минуты: Jupyter + numpy тормозит → оборачиваем функцию в .dtr → ×50 скорость → возвращаем в Python. Это то, чего не умеют Rust (порог), C (нельзя из Jupyter), Mojo (закрытый).
