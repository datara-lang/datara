## 0. Цель релиза одной фразой и метрики победы

### 0.1. Цель

Пользователь пишет на Datara, не знает на каком языке написана библиотека (Python, JS, Rust, Go, C#, Zig, JVM, Lua, C/C++),
вызывает её как свою, платит налог в наносекундах, а в одном процессе связка `python + js + rust` работает быстрее,
чем три отдельных микросервиса, соединённых через JSON и HTTP.

Слоган релиза для README:

> «Datara поставляется с 2.7 млн пакетов. Мы не переписывали numpy — мы сделали его быстрым.»

### 0.2. Метрики победы (гейт релиза — всё должно быть измерено)

Таблица налогов на один вызов чужой функции (медиана, честный замер на одной машине):

| Язык-источник | Было (1.5.0) | Должно стать (1.5.1) | Как меряем |
|---|---|---|---|
| C / C++ | 0 нс | 0 нс (удержать) | цикл 1M прямых вызовов |
| Rust (через C-ABI) | 0 нс | 0 нс (удержать) | цикл 1M вызовов через обёртку |
| Zig | 0 нс | 0 нс | цикл 1M вызовов |
| Lua | ~20 нс | 20 нс или меньше | цикл 1M вызовов |
| Go (через c-shared) | ~100+ нс | 30 нс | цикл 1M вызовов |
| C# (через NativeAOT) | ~100+ нс | 15 нс | цикл 1M вызовов |
| JS / NPM (через изолят) | 169 нс | 40 нс | цикл 1M вызовов |
| Python | 5500 нс (5.5 мкс) | 40 нс (Tier 2) и 0–5 нс (Tier 3) | цикл 1M вызовов |
| JVM (через shared-объект) | ~200+ нс | 50 нс | цикл 1M вызовов |

Смешанный вызов `python + js + rust` в одной функции: было ~6000 нс + до 20 мс если через JSON между процессами,
должно стать ~120 нс в одном процессе без сериализации.

Демо-обязательство: `Datara + numpy sum(1M)` быстрее `Python + numpy sum(1M)` в 1.3–1.5 раза
за счёт обхода Python-обвязки и прямого вызова C-ядра.

### 0.3. Что значит «топ-1 продакшн» (Definition of Done кратко, полное — в главе 9)

1. Новичок не учит чужие языки, чтобы пользоваться чужими либами.
2. Налог везде измерен и укладывается в таблицу выше.
3. Смешанный пример на трёх языках работает в одном файле без JSON.
4. Новые пакеты в Sparks ставятся одной командой и находятся поиском.
5. Ни один пример из 1.5.0 не сломан.

## 1. Что уже есть в 1.5.0 — инвентаризация (чтобы не делать дважды)

### ЗАЧЕМ эта глава

Исполнитель обязан знать, что уже готово, чтобы не переписывать готовое и не сломать рабочее.
Всё ниже — уже есть и работает. В 1.5.1 это только используем как фундамент.

### 1.1. Язык и уровни (есть, не трогаем)

- Четыре уровня в одном файле: уровень 1 (простые скрипты через `val` / `mut`), уровень 2 (надёжные сервисы через контракты и ошибки), уровень 3 (быстрый системный код через виды на память и арены), уровень 4 (ядро и железо через регистры и ассемблер).
- Новичок никогда не видит указатели. Сеньор получает полный контроль. Уровни не переключаются конфигом — компилятор сам понимает уровень по коду.
- Правила языка, которые нельзя нарушать: нет знака `:=`, нет исключений `try/catch/throw`, строки в обычных кавычках без интерполяции (интерполяция только в специальных `fmt"..."` / `$"..."` / `f"..."`), делитель всегда проверяется на ноль, вместо классов — структуры, вместо наследования — плоская композиция, нет неявных преобразований чисел (только явные), любой вызов чужого C-кода — только внутри блока `unsafe` с обоснованием.

### 1.2. Ошибки и контракты (есть, используем поверх чужих либ)

- Тип `Outcome<T>` для ошибок и `Maybe<T>` для отсутствия значения. Раскрытие через `?` (вернуть ошибку наверх) и `or` (запасное значение).
- Контракты `require` (предусловие) и `ensure` (постусловие). Работают и поверх чужих библиотек.
- Пример смысла: чужая библиотека бросила ошибку — она автоматически становится `Outcome.err`, дальше работает обычный `or` / `?`, учить чужой механизм ошибок не надо.

### 1.3. Память (есть, используем для мостов)

- Три слоя памяти: слой 1 — компилятор сам ставит освобождение после последнего использования (ноль кода в рантайме); слой 2 — арены и пулы со сбросом за один такт; слой 3 — счётчик ссылок только для разделяемых замыканий.
- Команда `forgen inspect --memory` показывает, какой слой сработал на каждой строке.
- `view` — вид на чужую память без копирования. Арена на 64 КБ под запрос с освобождением за один такт.
- Команда `with arena = Arena::stack(size: 64.KB) { ... }` — вся память внутри блока умирает разом в конце блока.

### 1.4. Мосты 1.5.0 (есть, но с трением — это и чиним в 1.5.1)

Что уже умеем:

- C/C++: прямая строка `import c "заголовок.h" with link("библиотека")`, вызов за 0 нс.
- Rust: строка `use rust.имя_крейта`, сборка через Cargo в общую библиотеку, вызов за 0 нс.
- Python: строка `use python.имя_пакета`, внутри — выполнение строк кода и чтение переменных по одной, плюс привязка буфера без копирования. Налог большой (5.5 мкс), надо знать язык Python.
- JS/NPM: строка `use npm.имя_пакета`, налог 169 нс, есть сериализация местами.
- Go / C# / Zig / JVM / Lua: единый манифест зависимостей на все языки, установка одной командой. Реальных быстрых адаптеров пока только три (картинки, регулярки, JSON), остальные — заявлены, но не ускорены.
- Единый файл зависимостей держит версии всех языков сразу. Одна команда ставит всё (заголовки C, крейты Rust, пакеты Python, пакеты NPM, модули Go, проекты .NET, либы Zig, образы JVM).

В чём боль 1.5.0 (её и решает 1.5.1):

1. Чтобы пользоваться чужой либой, надо знать чужой язык (писать на Python внутри Datara).
2. Большой налог на каждый вызов (особенно Python).
3. Местами есть копирование и сериализация (JSON между языками).
4. Подсказки редактора не проваливаются в чужие либы.
5. Версии чужих либ живут отдельно от версий Datara-пакетов.

### 1.5. Sparks в 1.5.0 (есть база, нет мостов)

- Реестр по адресу Sparks: всего 5 пакетов (крипто-ядро, HTTP-роутер, детерминированный движок для игр, SIMD-математика, ключ-значение хранилище). Каждый пакет — архив + хэш + подпись Ed25519 + запись в индексе + файл разрешений (капабилити) + пример использования.
- Важно: bridge-проекций (тонких быстрых обёрток над чужими либами) там нет вообще. Идиоматичных обёрток (простые имена для поиска) тоже нет. Это и есть главная работа 1.5.1 в части пакетов.
- Путь реестра на диске известен исполнителю отдельно (спрашивать у человека, где лежит папка Sparks). Формат выкладки новых пакетов — ровно такой же, как у пяти существующих: архив, хэш, подпись, запись в индексе, файл разрешений, пример.

### 1.6. Тулинг 1.5.0 (есть, расширяем)

- Проверка типов за миллисекунды, запуск через быстрый и медленный бэкенды, просмотр памяти, доктор для мостов (меряет наносекунды), менеджер пакетов (добавить/ставить/проверить/искать), форматтер, документация, LSP (подсветка, переходы).
- Нет в 1.5.0: генератора обёрток из чужих типов, единой проверки мостов, честного бенча мостов. Это делаем в 1.5.1.

## 2. Единая модель для ВСЕХ языков — 3 тира (ядро идеи 1.5.1)

### ЗАЧЕМ

Нельзя делать отдельный мост на каждый язык — утонем в поддержке.
Делаем один общий движок мостов (Bridge-Core) + три тира использования.
Пользователь не выбирает тир напрямую — он пишет код своего уровня (1-4), а тир подбирается сам.
Старый строковый способ продолжает работать. Новый типизированный — рядом, аддитивно.

### 2.1. Таблица тиров

| Тир | Как пишет пользователь | Надо ли знать чужой язык | Налог | Для чего |
|---|---|---|---|---|
| Tier 1: Строковый (уже есть) | Выполнить строку чужого кода, прочитать переменную | Да | Python 5.5 мкс, JS 169 нс | Прототип за 30 секунд, клей, разовый скрипт |
| Tier 2: Типизированная проекция (по умолчанию для ВСЕХ либ) | use python.numpy as np затем np.sum(a) как своя функция | Нет | 30-80 нс, цель 40 нс | Весь продакшен, ничего настраивать не надо |
| Tier 3: Прямое ядро из той же либы (включается ОДНОЙ СТРОЧКОЙ на конкретную либу) | Та же строка use + модификатор with fast (см. 2.4) | Нет | 0-5 нс | Горячий цикл, где человек сам захотел минимум задержки |

Соответствие уровням языка: уровень 1 (новичок) пишет Tier 2 и не знает, что это Python или JS.
Уровень 4 (сеньор) добавляет with fast к нужной либе и получает 0 нс через прямой вызов ядра из той же скачанной либы.

### 2.4. НОВОЕ: человек сам выбирает тир для ЛЮБОЙ либы одной строчкой (решение человека)

ВАЖНОЕ ПРАВИЛО: по умолчанию каждая либа работает на Tier 2 (не надо запариваться).
Если человек хочет минимальную задержку на конкретной либе — он просит Tier 3 для ЭТОЙ либы явно.
Отдельно скачивать что-то для Tier 3 НЕ надо — быстрое ядро берётся из уже скачанной либы автоматически.

КАК ДОЛЖНО ВЫГЛЯДЕТЬ (три способа, все равнозначны, исполнитель делает все три):

Способ А — модификатор в строке use (для одного файла):

```
use python.numpy as np with fast
use npm.lodash as lo
use rust.regex as re with fast
```

Смысл: numpy и regex едут на Tier 3 (0-5 нс, ядро из той же либы), lodash остаётся на Tier 2 (40 нс, человек не захотел запариваться).

Способ Б — запись в манифесте (для всего проекта сразу):

```
[bridges.fast]
python.numpy = true
rust.regex = true
```

Смысл: весь проект использует Tier 3 для этих двух либ, остальные либы — Tier 2. Одна галочка на либу.

Способ В — блок nogil + fast_sum для горячего куска (для сеньора, точечно):

```
nogil {
    let s = fast_sum(v)
}
```

Смысл: только этот кусок едет без блокировки и без аллокаций, остальной файл — обычный Tier 2.

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Добавить в язык модификатор with fast к строке use (работает для use python.*, use npm.*, use rust.*, use go.*, use csharp.*, use zig.*, use java.*, use lua.*, import c).
2. Добавить секцию [bridges.fast] в манифест: имя либы = true/false. По умолчанию false (Tier 2).
3. Правило разрешения: модификатор в файле сильнее манифеста (файл перебивает проект).
4. Если для либы Tier 3 невозможен (внутри либы нет быстрого ядра) — НЕ ронять сборку, а оставаться на Tier 2 + выдать подсказку «для этой либы Tier 3 невозможен, потолок — 40 нс».
5. Команда проверки мостов обязана показывать тир каждой либы: имя — тир 2/3 — налог в нс.
6. Дока: одна страница «как включить минимум задержки на мою либу за 1 минуту» с тремя способами выше.

КАК ПРОВЕРИТЬ: один и тот же файл собирается дважды — без with fast (все Tier 2, бенч 40 нс) и с with fast на одной либе (эта либа 0-5 нс, остальные 40 нс). Переустановка пакетов не требуется.
ЧАСТЫЕ ОШИБКИ: требовать Tier 3 молча без подсказки когда ядра нет; заставлять качать второй пакет для Tier 3 (ЗАПРЕЩЕНО — ядро берётся из той же либы); модификатор, который действует на весь проект вместо одной либы.

### 2.2. Почему связка трёх языков станет быстрее трёх сервисов

Три отдельных сервиса платят: сериализация в JSON + сеть + три сборщика мусора + блокировки.
Один процесс на Datara платит: ноль копий (общий вид на память) + одна арена (освобождение за такт) + общие ошибки.

Было: данные в JSON (5 мс) в Python (2 мс) в JSON (2 мс) в JS (1 мс) в JSON в Rust = около 8-10 мс + паузы.
Должно стать: данные лежат в арене, три либы вызываются по указателю без копий = около 0.8 мс и ноль пауз.

### 2.3. Почему Datara может быть быстрее хозяина на его же либе

Почти все быстрые либы (numpy, torch, lodash, regex) — это быстрое C-ядро + медленная обвязка на хозяине.
Хозяин платит за обвязку всегда. Datara вызывает ядро напрямую, обвязку пропускает.
Пример: Python с numpy платит 5.5 мкс налога (байткод, упаковка кортежа, GIL, поиск в словаре).
Datara Tier 3 платит 0-5 нс (прямой переход по адресу, адрес известен заранее).
Итог: на той же C-функции Datara быстрее Python в 1.3-1.5 раза по физике.

## 3. Синтаксис — как это выглядит для пользователя (Datara-way, ничего не ломает)

### ЗАЧЕМ

Синтаксис уже почти идеален (use python.numpy as np). Его не ломаем, а дополняем проекцией типов:
пользователь пишет как на Datara, подсказки как на Datara, ошибки как на Datara.

### 3.1. Было в 1.5.0 (Tier 1 — надо знать Python, оставляем для прототипов)

КАК ВЫГЛЯДЕЛО:

> Создать объект Python, выполнить строку с импортом и формулой, затем прочитать переменную по одной
> с запасным значением через or. Минус: надо знать синтаксис Python, API numpy, что такое eval_float.

Оставляем без изменений для быстрых проб.

### 3.2. Становится в 1.5.1 (Tier 2 — писать как на Datara, языка не знать)

КАК ДОЛЖНО ВЫГЛЯДЕТЬ (канон, учить наизусть):

```
use python.numpy as np
use python.numpy.linalg as la
use npm.lodash as lo
use rust.regex as re
import c "sqlite3.h" with link("sqlite3")

fn main() -> Outcome<Int> {
    let m: NDArray<Float> = np.eye(3)
    let det: Float = la.det(m) or 0.0
    require det != 0.0

    let data: List<Int> = [1, 2, 3]
    let filtered = lo.filter(data, x => x > 1)

    let ok: Bool = re.is_match("hello 123", r"\d+") or false

    let v: view NDArray = m.view()
    out fmt"det={det} filtered={filtered} ok={ok}"
}
```

Почему это в духе языка:

- Типы — типы Datara (NDArray, List, Float, Bool), а не чужие PyObject / JSValue. Редактор подсказывает из чужих типовых файлов, но показывает как Datara.
- Ошибки чужих либ (Python raise, JS throw, Rust panic на границе) автоматически становятся Outcome.err. Работают привычные ? и or.
- Контракты require / ensure работают поверх чужих либ (пример выше: require det != 0.0 вместо проверки исключения Python).
- view — вид на память без копирования (List в Datara, ndarray в Python, Array в JS — одна память).
- Динамическое значение из чужого языка принимается в val без упаковки, а проверка if x is Int делает его статическим (сужение типов).
- unsafe с обоснованием — только для Tier 3 прямых вызовов ядра.

### 3.3. Tier 3 для сеньора (0 нс, hot loop)

КАК ДОЛЖНО ВЫГЛЯДЕТЬ:

```
@no_alloc
fn fast_sum(arr: view NDArray) -> Float {
    unsafe(justification: "прямое ядро числовой либы, проверено проекцией типов") {
        return c_numpy_sum(arr.ptr, arr.len)
    }
}

nogil {
    let s = fast_sum(v)
}
```

Смысл: прямой вызов C-функции по указателю и длине, ноль аллокаций (атрибут no_alloc это гарантирует),
блок nogil снимает глобальную блокировку Python, чтобы 4 потока работали параллельно в 4 раза быстрее хозяина.

### 3.4. Смешанный пайплайн — три языка в одном процессе без сериализации

КАК ДОЛЖНО ВЫГЛЯДЕТЬ:

```
use python.numpy as np
use npm.lodash as lo
use rust.rayon as rayon

fn pipeline(data: List<Float>) -> List<Float> {
    with arena = Arena::stack(size: 64.KB) {
        let a: view NDArray = np.array(data).view()
        let b = lo.chunk(a, 1000)
        return rayon.par_iter(b).map(fast_sum).collect()
    }
}
```

Смысл: одна арена на все три языка, виды на память без копий, освобождение всего за один такт в конце блока.

### КАК ПРОВЕРИТЬ главу 3

- Три примера выше компилируются и выполняются (Tier 2 — обязательно, Tier 3 — хотя бы для одной либы).
- Подсказки редактора показывают np.eye / lo.filter / re.is_match с доками на языке Datara.
- Ошибка чужой либы (например деление на ноль в чужой функции) превращается в Outcome.err и ловится через or.
- ГЕЙТ: новичок, не знающий Python, повторяет пример Tier 2 за 10 минут по доке.

## 4. Как убрать налог до нуля для ВСЕХ языков — 5 техник общего движка

### ЗАЧЕМ

Один движок + маленькие переходники под каждый язык. Не делаем 9 разных мостов — делаем 1 движок и 9 тонких переходников.
Каждая техника ниже убирает один вид налога. Вместе они дают таблицу из главы 0.

### Техника 1. Адрес функции известен заранее + кэш первого вызова

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Когда пользователь пишет use python.numpy.linalg и вызывает det, компилятор на этапе проверки типов находит адрес этой функции один раз.
2. Первый вызов ищет медленно (как обычно), запоминает адрес в кэш.
3. Все следующие вызовы идут прямо по адресу без поиска по словарю.
4. Кэш хранит пару имя-адрес, сбрасывается при смене версии либы.

КАК ПРОВЕРИТЬ: бенч 1M вызовов — время падает с 5500 нс до около 80 нс уже на этой технике.
ЧАСТЫЕ ОШИБКИ: забыть сброс кэша при обновлении либы; кэшировать адрес до загрузки либы.

### Техника 2. Вызов без упаковки (безтупловый ABI)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Не упаковывать аргументы в кортеж/словарь/объект, как делают хозяева.
2. Класть указатель и длину прямо в регистры процессора, как обычный C-вызов.
3. Ноль аллокаций на вызов, проверить атрибутом no_alloc в горячем пути.
4. Для каждого типа Datara зафиксировать раскладку в регистрах (число — значением, список — указатель+длина, строка — указатель+длина).

КАК ПРОВЕРИТЬ: счётчик аллокаций на 1M вызовов равен нулю; время падает ещё на 60-80 процентов.
ЧАСТЫЕ ОШИБКИ: передать строку без длины; перепутать порядок указатель/длина.

### Техника 3. Обход блокировок и копий (GIL, изоляты, JSON)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Добавить блок nogil { ... } — внутри глобальная блокировка Python снята, звать можно только проверенные C-ядра (иначе ошибка компилятора).
2. Перейти на свободнопоточный интерпретатор Python (версия без GIL), держать его внутри одного процесса.
3. Для JS держать один изолят на процесс, память передавать видом на буфер без JSON.stringify (буфер на арене Datara).
4. Вместо копирования List в чужой массив — отдавать view на ту же память.
5. Если код гонит данные через JSON между языками внутри одного процесса — выдавать подсказку используй view.

КАК ПРОВЕРИТЬ: 4 потока считают сумму параллельно с ускорением близко к 4x; копий ноль.
ЧАСТЫЕ ОШИБКИ: снять GIL и позвать неготовую функцию; освободить арену раньше, чем умер view.

### Техника 4. Прямое ядро ИЗ УЖЕ СКАЧАННОЙ либы (Tier 3 без отдельных пакетов, включается по желанию)

ВАЖНОЕ ПРАВИЛО (решение человека): человек качает ОДНУ обычную либу (как обычно через менеджер пакетов),
а Tier 3 получается ИЗ НЕЁ ЖЕ автоматически. Никаких отдельных пакетов с суффиксом _core качать не надо.
Отдельные _core-пакеты НЕ делаем — это лишний мусор в реестре и путаница.

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Человек ставит либу как обычно (пример: numpy через python-зависимости, lodash через npm, regex через крейты).
2. По умолчанию ВСЁ работает на Tier 2 (40 нс, ничего делать не надо, запариваться не надо).
3. Если человек хочет минимум задержки на конкретной либе — он одной строчкой просит Tier 3 для ЭТОЙ либы
   (как просить — смотри главу 2.4 ниже: модификатор with fast или запись в манифесте).
4. Компилятор сам находит C-ядро ВНУТРИ уже скачанной либы (математическое ядро numpy, движок torch,
   ядро JS-движка, общая Rust-библиотека, архив C для Go, образ для C# и JVM) и зовёт его напрямую,
   минуя рантайм хозяина. Отдельно скачивать ядро НЕ надо — оно уже лежит внутри скачанной либы.
5. Если ядро найти нельзя (либа чисто на хозяине без C-ядра) — честно остаётся Tier 2 + подсказка
   «для этой либы Tier 3 невозможен, потолок — 40 нс», без ошибки сборки.
6. Внутри быстрого вызова только unsafe с обоснованием и no_alloc, снаружи обычная функция с Outcome.

КАК ПРОВЕРИТЬ: человек скачал ОДИН пакет numpy, включил fast одной строкой — демо sum(1M) быстрее Python в 1.3-1.5 раза.
Без строки fast — те же вызовы работают на Tier 2 без переустановки.
ЧАСТЫЕ ОШИБКИ: привязка к приватному символу ядра (пинать версию!); путаница int 32 vs 64; требовать Tier 3 там, где ядра нет.

### Техника 5. Память чужих объектов под контролем (ноль утечек)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Чужой объект живёт как счётчик ссылок: создался — вверх, последнее использование — вниз автоматически.
2. view — вид без счётчика вообще.
3. Просмотр памяти показывает и чужие объекты: где создан, где освобождён, каким слоем.
4. Тест на утечки: цикл 1M созданий чужих объектов — счётчик утечек равен нулю.

КАК ПРОВЕРИТЬ: тест на утечки зелёный; просмотр памяти показывает строку освобождения объекта Python.

### Сводный гейт главы 4

C 0 нс, Rust 0 нс, Zig 0 нс, C# 15 нс, Go 30 нс, JS 40 нс, Python 40 нс (Tier 2) и 0-5 нс (Tier 3), JVM 50 нс, Lua 20 нс.
Смешанный вызов трёх языков — около 120 нс.

## 5. Единый Polyglot Runtime — чтобы три языка были быстрее трёх сервисов

### ЗАЧЕМ

Сейчас в индустрии Python + JS + Rust соединяют через HTTP и JSON. Это медленно и сложно.
Мы делаем один процесс, одну арену, одни ошибки. Тогда связка быстрее каждой части по отдельности.

### 5.1. Что собрать (состав рантайма)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Один процесс содержит внутри: под-интерпретатор Python без GIL + изолят JS + общие Rust-библиотеки + C-библиотеки.
2. Все делят: одну арену на запрос (64 КБ, сброс за такт), виды на память без копий, единый тип ошибок Outcome.
3. Запуск одной командой собирает всё вместе, версии всех частей пинятся в одном манифесте.
4. Падение одной чужой либы превращается в Outcome.err и не роняет процесс (паник-барьер на границе).

### 5.2. Пример, где мы быстрее по отдельности (обязательное демо релиза)

КАК ДОЛЖНО ВЫГЛЯДЕТЬ:

```
use python.numpy as np
use npm.lodash as lo
use rust.rayon as rayon

fn pipeline(data: List<Float>) -> List<Float> {
    with arena = Arena::stack(size: 64.KB) {
        let a: view NDArray = np.array(data).view()
        let b = lo.chunk(a, 1000)
        return rayon.par_iter(b).map(fast_sum).collect()
    }
}
```

Смысл: массив из Datara без копий уходит в Python, чанки режутся JS-ядром на той же памяти,
параллельный обход едет Rust-ядром за 0 нс, всё освобождается за такт.

Через микросервисы это было бы: данные в JSON в Python (5 мс) в JSON в JS (2 мс) в JSON в Rust (1 мс) = 8 мс + сборки мусора.
У нас: 0.8 мс и ноль сборок мусора.

### 5.3. Ниши, где Polyglot Runtime даёт 10 из 10 (дополнительно к базе 1.5.0)

1. Быстрые скрипты с тяжёлыми либами (CSV 1 ГБ через таблицы, картинки, JSON): удобство 9 из 10, скорость 10 из 10. У хозяина удобство 10, скорость 4.
2. Бэкенд с математикой (HTTP + numpy без GIL + фиберы без раскраски): 10 из 10 против 6 у хозяина на GIL.
3. Геймдев (физика на numpy-ядре + чанки JS + параллелизм Rust): 10 из 10.
4. Embedded-фильтры (только Tier 3, без интерпретатора вообще): 10 из 10.
5. AI-инференс без окружения хозяина (один exe без conda): 10 из 10 в деплое.
6. WASM-фронт без пауз сборки мусора: 9 из 10 (10 после браузерного ядра, это уже следующий релиз).

### КАК ПРОВЕРИТЬ главу 5

- Демо pipeline выше собирается одной командой и проходит без JSON между языками.
- Замер времени демо против связки через JSON — выигрыш минимум в 5 раз.
- Падение чужой функции не роняет процесс (возвращается Outcome.err).
- ГЕЙТ: таблица «микросервисы vs Polyglot Runtime» в доке с честными цифрами с одной машины.

## 6. Sparks в 1.5.1 — какие пакеты добавить и как выкладывать (без отдельных _core)

### ЗАЧЕМ

Реестр уже умеет выкладывать пакеты правильно (архив + хэш + подпись + индекс + разрешения + пример).
В 1.5.0 там 5 базовых пакетов. В 1.5.1 добавляем только идиоматичные обёртки (тонкий Datara-слой, который внутри
зовёт чужие либы через Tier 2, а при with fast — через Tier 3 из ТОЙ ЖЕ либы). Отдельных пакетов-ядер НЕ делаем.

### 6.1. Что добавить (две пачки, всего 10 пакетов, все — обёртки, не ядра)

Пачка А — идиоматичные обёртки для поиска (прячут чужой синтаксис, дают Datara-типы и Outcome):

1. mathx — математика поверх числовой Python-либы (гладкие вектора/матрицы, сумма, детерминант). Внутри Tier 2, при with fast — ядро из той же либы.
2. strx — строки поверх C-строк и регулярок (сплит, поиск, замена). Внутри Tier 2.
3. jsonx — JSON поверх существующего JSON-моста (парсинг в Datara-типы, сериализация без копий через view).
4. resultx — helpers для Outcome/Maybe (цепочки or, сбор ошибок из чужих либ в одну).
5. webx — HTTP-клиент/сервер поверх NPM-мира (роуты, JSON, статика), но с Datara-сигнатурами.

Пачка Б — готовые связки под ниши (тоже обёртки, не ядра, каждая тянет обычную чужую либу как зависимость):

6. datax — таблицы и CSV поверх табличной Python-либы (загрузил CSV 1 ГБ за ~2 сек вместо 22 сек у хозяина).
7. torcx — инференс поверх движка torch (один вызов — один тензор, без окружения хозяина в рантайме демо).
8. jsx — чанки/мапы/фильтры поверх JS-мира (chunk, filter, map через view без JSON).
9. rgxx — регулярки и параллельный обход поверх Rust-мира (0 нс, уже есть задел из трёх адаптеров).
10. sqlx — база поверх C-драйвера (открыть, запрос, закрыть, всё через Outcome, 0 нс).

ЗАПРЕЩЕНО: пакеты с суффиксом _core (numpy_core, torch_core и т.п.). Быстрое ядро достаётся из уже скачанной
чужой либы через with fast, второй пакет качать не надо. Если будешь делать _core — остановись, это ошибка.

### 6.2. Как выкладывать каждый пакет (процедура как у пяти существующих, шаг в шаг)

ЧТО СДЕЛАТЬ ПО ШАГАМ для каждого из 10 пакетов:
1. Собрать папку пакета: код обёртки + файл описания (имя, версия, описание, автор, лицензия, теги, разрешения-капабилити, пример использования).
2. В примере использования — только Datara-код (без строк на чужом языке), пример обязан компилироваться.
3. Упаковать в архив, посчитать хэш архива.
4. Подписать архив тем же ключом, что подписаны пять существующих (тот же key_id).
5. Положить архив в папку архивов реестра, добавить JSON-описание в папку описаний.
6. Добавить запись в общий индекс: имя, версия, описание, автор, лицензия, разрешения, теги, ссылка на архив, хэш, подпись, ключ, пример, ридми.
7. Увеличить счётчик пакетов в индексе на 1.
8. Проверить установкой: команда добавить пакет ставит его, команда проверить подпись — зелёная, команда искать — находит по имени и тегам, пример из описания собирается.
9. В описании каждой обёртки честно указать: какая чужая либа тянется как зависимость (имя + версия), какой тир по умолчанию (Tier 2), что даёт with fast (Tier 3 из той же либы или подсказка что невозможен).

КАК ПРОВЕРИТЬ: все 10 ставятся по одному, поиск находит каждый по имени, примеры из описаний собираются,
подписи зелёные, счётчик в индексе равен 15 (5 старых + 10 новых).
ЧАСТЫЕ ОШИБКИ: забыть увеличить счётчик; пример в описании не компилируется; разрешения-капабилити не указаны
(пакет с сетью без Capability — запрещён, сборка обязана падать); зависимость на чужую либу без пина версии.

### 6.3. Гейт главы 6

Поиск по реестру находит все 10 по именам mathx/strx/jsonx/resultx/webx/datax/torcx/jsx/rgxx/sqlx.
Переход к определению из Datara-кода ведёт в обёртку (а не в чужой site-packages).
Ни один из 5 старых пакетов не сломан (их примеры собираются как раньше).
## 7. Тулинг — команды генератора, проверки и бенча (чтобы новичок поверил за 10 минут)

### ЗАЧЕМ

Без трёх команд мосты не взлетят: генератор обёрток (не знать язык), проверка (убедиться что всё зелёное),
бенч (увидеть наносекунды). Старые команды не трогаем, добавляем три новые рядом.

### 7.1. Команда 1: генератор обёрток из чужих типов

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Команда принимает имя чужой либы (пример: python.numpy, npm.lodash, rust.regex) и папку вывода.
2. Для Python читает типовые файлы описаний (.pyi из typeshed), для JS — типовые описания (.d.ts),
   для Rust — метаданные Cargo, для C — заголовок (уже умеем), для Go/C#/Zig/JVM/Lua — их описания API.
3. Генерирует Datara-обёртку: каждая чужая функция становится Datara-функцией с Datara-типами,
   чужие ошибки становятся Outcome.err, доки из чужих docstring становятся Datara-доками с примером на Datara.
4. Сгенерированная обёртка внутри держит Tier 2 вызовы, а при with fast — Tier 3 вызовы ядра из той же либы.
5. Сгенерированный файл обязан компилироваться без ручных правок.

КАК ДОЛЖНО ВЫГЛЯДЕТЬ использование:
> сгенерировать обёртку для python.numpy в папку мостов, затем use python.numpy as np начинает подсказывать np.eye с доками.

КАК ПРОВЕРИТЬ: генерация для numpy/lodash/regex завершается с кодом 0, файлы компилируются,
редактор подсказывает три функции с доками.
ЧАСТЫЕ ОШИБКИ: генератор требует ручных правок (запрещено); доки остаются на чужом языке без примера на Datara.

### 7.2. Команда 2: единая проверка мостов (видит тиры и версии)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Команда читает манифест (включая секцию bridges.fast), проверяет каждую либу: установлена ли, версия совпадает ли,
   тир какой (2 по умолчанию, 3 если with fast и ядро нашлось), налог сколько.
2. Вывод — одна строка на либу: имя — ок/ошибка — тир 2/3 — налог в нс — версия.
3. Если для либы с with fast ядро не нашлось — строка жёлтая: тир 2, подсказка «Tier 3 невозможен, потолок 40 нс», код выхода всё равно 0 (не роняем сборку).
4. Если версия не совпала или либа не стоит — красная строка + точная команда установки, код выхода ненулевой.

КАК ПРОВЕРИТЬ: на проекте с тремя либами (одна с fast) вывод показывает две строки Tier 2 и одну Tier 3 с наносекундами.
ЧАСТЫЕ ОШИБКИ: проверка не видит with fast из файла (читает только манифест); налог не меряет, а выдумывает.

### 7.3. Команда 3: честный бенч мостов (доказательство топ-1)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Команда гоняет цикл 1M вызовов для каждой подключённой либы, меряет медиану налога, сравнивает с таблицей главы 0.
2. Отдельный сценарий: смешанный вызов трёх языков в одной функции (замер около 120 нс).
3. Отдельный сценарий: демо sum(1M) Datara против хозяина (победа 1.3-1.5x при with fast).
4. Вывод — таблица как в главе 0 + пометка зелёная/красная по каждому языку. Цифры честные с одной машины, без подгона.

КАК ПРОВЕРИТЬ: таблица сошлась с гейтом главы 0 или честно зафиксировано отставание с разбором почему.
ЧАСТЫЕ ОШИБКИ: мерять один вызов вместо медианы миллиона; мерять на разных машинах и сравнивать.

### 7.4. Манифест: одна секция для всего (пример канона)

КАК ДОЛЖНО ВЫГЛЯДЕТЬ:

```
[bridges]
python = "3.13t"
numpy = "2.0"
tokio = "1.40"
express = "4.18"

[bridges.fast]
python.numpy = true
rust.regex = true
```

Смысл: верхняя секция — версии (пинаются как Sparks-пакеты, с подписью), нижняя — какие либы едут на Tier 3.
Остальные либы — Tier 2 по умолчанию. Одна команда установки ставит всё.

### Гейт главы 7

Три команды работают, дока «мой первый мост за 10 минут» проходится новичком без знания чужих языков,
таблица бенча опубликована в доке релиза.

## 8. Пошаговый план 8 недель (порядок строгий, всё аддитивно, старое не ломаем)

### Правила недель

- Одна неделя — один гейт. Без зелёного гейта дальше не идём.
- После каждой недели: сборка без варнингов, все тесты зелёные, смоук-пример ошибок из 1.5.0 проходит.
- Старый строковый способ (Tier 1) обязан работать на каждой неделе без изменений.

### Недели 1-2: проекция типов (убираем надо знать язык)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Научить компилятор читать чужие типовые описания: Python (типовые файлы), JS (типовые описания), Rust (метаданные Cargo), остальные — их описания API. Начать с трёх: числовая либа, JS-мир, Rust-регулярки.
2. Сделать команду генератора обёрток (глава 7.1): на вход имя либы, на выход Datara-файл с функциями и доками.
3. Строка use python.numpy as np начинает давать подсказки np.eye и np.sum с Datara-типами и Datara-доками.
4. Чужие ошибки маппятся в Outcome.err. Проверить через or и ?.
5. Чужие доки перерендерить с примером на Datara.
6. Модификатор with fast на этом этапе парсится, но пока ни на что не влияет (влияние появится на неделе 6).

ГЕЙТ НЕДЕЛЬ 1-2: пример Tier 2 из главы 3.2 компилируется; редактор подсказывает три функции; ошибка чужой либы ловится через or; новичок повторяет пример за 10 минут.

### Недели 3-4: общий движок + кэш (убираем налог на 90 процентов)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Собрать общий движок вызовов: одна функция позвать чужую функцию по кэшированному адресу без упаковки.
2. Переходники под языки: Python (кэш + вызов), JS (кэш + вызов), Rust/C/Zig (прямой адрес, уже 0 нс, удержать), Go/C#/JVM/Lua (тонкие переходники через их C-образы).
3. Первый вызов медленный (ищет и запоминает), остальные — прямо по адресу.
4. Аргументы класть в регистры без кортежей (техника 2), проверить ноль аллокаций атрибутом no_alloc.
5. Прогнать бенч: цель Python 5500 нс до около 80 нс, JS 169 нс до около 40 нс уже здесь.

ГЕЙТ НЕДЕЛЬ 3-4: бенч 1M показывает падение налога минимум в 10 раз; аллокаций ноль; старые примеры 1.5.0 зелёные.

### Неделя 5: zero-copy + память + nogil (убираем копии и блокировки)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Расширить привязку буфера на view для всех языков: List Datara — одна память с чужим массивом, ноль копий.
2. JS-буфер держать на арене Datara (вид без JSON.stringify).
3. Чужие объекты перевести на авто-счётчик (техника 5): создать — вверх, последнее использование — вниз, view — без счётчика.
4. Добавить блок nogil { ... }: внутри только проверенные вызовы, иначе ошибка с подсказкой.
5. Подключить свободнопоточный Python без GIL как под-интерпретатор; проверить параллель x4.
6. Просмотр памяти показывает чужие объекты (где создан, где освобождён).
7. Диагностика: JSON между языками внутри одного процесса подсвечивается подсказкой используй view.

ГЕЙТ НЕДЕЛИ 5: копий ноль; 4 потока дают ускорение близко к 4x; тест утечек 1M зелёный; просмотр памяти показывает строку освобождения объекта Python.

### Недели 6-7: Tier 3 из той же либы по желанию (добиваем быстрее хозяина)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Доделать модификатор with fast: теперь он реально переключает ЭТУ либу на прямое ядро из ТОЙ ЖЕ скачанной либы (техника 4). Переустановка не нужна.
2. Доделать секцию [bridges.fast] в манифесте (файл сильнее манифеста).
3. Покрыть Tier 3 пять связок: числовая Python-либа, табличная Python-либа, движок torch, JS-мир, Rust-мир. Для каждой: with fast даёт 0-5 нс, без fast — честные 40 нс.
4. Если ядра внутри либы нет — остаться на Tier 2 + жёлтая подсказка (не ронять сборку).
5. Собрать демо sum(1M): один пакет скачан один раз, без fast — как хозяин, с fast — быстрее хозяина в 1.3-1.5 раза.
6. Собрать демо pipeline трёх языков из главы 5.2 с выигрышем минимум x5 против JSON-связки.

ГЕЙТ НЕДЕЛЬ 6-7: один и тот же файл без with fast — Tier 2 везде; с with fast на одной либе — эта либа 0-5 нс; демо победы воспроизводится; вторых _core-пакетов нет (в индексе нет имён на _core).

### Неделя 8: манифест + проверка + пакеты + дока (релизная упаковка)

ЧТО СДЕЛАТЬ ПО ШАГАМ:
1. Зафиксировать секции [bridges] и [bridges.fast] в манифесте (пример из главы 7.4), версии пинятся с подписью как Sparks.
2. Доделать команду проверки мостов (глава 7.2): строка на либу с тиром и наносекундами.

## 10. Свои концепты 1.5.1 — чего не хватало разработчику (дополнительно к переписке)

### ЗАЧЕМ

Переписка закрыла скорость и удобство. Ниже — пять вещей, без которых топ-1 продакшн не бывает:
разработчик должен доверять чужой либе, чинить её, обновлять и откатывать без страха.

### 10.1. Единый контракт поверх чужих либ (require/ensure + Outcome для всех)

ЧТО СДЕЛАТЬ: контракты require/ensure работают поверх ЛЮБОЙ чужой функции (не только Python).
Пример смысла: require детерминант не ноль перед обращением матрицы из чужой либы — проверка на стороне Datara,
хозяина не трогаем. Нарушение контракта чужой либой превращается в Outcome.err с именем либы и аргументами.
КАК ПРОВЕРИТЬ: тест — чужая функция вернула мусор, контракт поймал, программа вернула Outcome.err вместо падения.

### 10.2. Песочница чужих либ (capability неизбежны даже для Tier 3)

ЧТО СДЕЛАТЬ: чужая либа не получает сеть/файлы/процессы автоматически. Вызывающий код обязан держать разрешение,
иначе сборка падает с понятной ошибкой. Правило действует и для прямого ядра (unsafe разрешает указатели,
но НЕ разрешает сеть/файлы). Пакет с сетью без разрешения в описании — не ставится.
КАК ПРОВЕРИТЬ: негативные тесты — вызов сетевой чужой функции без разрешения падает на проверке; с разрешением — работает.

### 10.3. Заморозка версий + откат одной командой (vendoring без боли)

ЧТО СДЕЛАТЬ: файл заморозки фиксирует точные версии всех чужих либ (Python, NPM, крейты, все девять миров) + хэши.
Одна команда ставит ровно замороженное, одна команда откатывает обновление. Обновление чужой либы без обновления
заморозки — предупреждение сборки. Кэш адресов (техника 1) сбрасывается при смене версии автоматически.
КАК ПРОВЕРИТЬ: обновил либу — сборка предупредила; откатил — всё зелёное; кэш не врёт после отката.

### 10.4. Сквозная отладка (стектрейс через границу языков)

ЧТО СДЕЛАТЬ: падение внутри чужой либы показывает сквозной стектрейс: строка Datara -> имя чужой функции ->
строка Datara. Просмотр памяти показывает чужие объекты (глава 4, техника 5). Отладчик обязан шагать через границу
хотя бы на уровне «вошёл в чужую функцию / вышел с Outcome».
КАК ПРОВЕРИТЬ: демо падения в чужой функции — стектрейс содержит и Datara-строки, и чужие имена.

### 10.5. Оценка покрытия ниш после 1.5.1 (куда выходим 9-10 из 10)

- Быстрые скрипты с тяжёлыми либами: 10 из 10 (быстрее хозяина, удобство Tier 2).
- Бэкенд + математика без GIL: 10 из 10.
- Геймдев (SoA + ядра + параллелизм): 10 из 10.
- Embedded-фильтры Tier 3 без интерпретатора: 10 из 10.
- Системное/драйверы (C 0 нс + контракты + песочница): 9 из 10 (10 после bare-metal всех плат в 1.5.2+).
- Data/AI-инференс (деплой одним exe): 10 из 10 в деплое, 9 из 10 в обучении (обучение остаётся у хозяина — и это нормально).
- Веб-фронт WASM без пауз: 9 из 10 (10 после браузерного ядра в 1.5.2+).
- Обычные скрипты где хозяин 10 из 10 за удобство: мы 9 из 10 + 10 из 10 в под-нише быстрых скриптов. Вытеснять хозяина оттуда не надо.
